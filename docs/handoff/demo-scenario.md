# 매듭 졸업 시연 시나리오 (해결점 A~M 적용 후)

> 시연 SoT 문서. 시나리오 변경 시 본 파일 직접 수정 → 다른 문서는 본 파일 참조.

## 배경

대학 동기 3명(지민, 수현, 민수)이 오랜만에 만나려고 함. 카톡에선 "언제 돼?" "나는 금요일" "난 토요일" 하다가 흐지부지 — 매듭이 해결.

## 참여자

- **지민** (방장, 캘린더 연동 O)
- **수현** (멤버, 캘린더 연동 O)
- **민수** (게스트, 캘린더 연동 X — 링크로 입장)

## 예상 소요: 3~4분

---

## ACT 1. 방 생성 & 입장 (30초) — 변경 없음

| Step | 누가 | 행동 | 시스템 반응 |
| --- | --- | --- | --- |
| 1 | 지민 | 메인 화면 → "모임 생성" 클릭 | 모임 생성 페이지 이동 |
| 2 | 지민 | 모임명: `이번 주 저녁 약속` / 카테고리: `식사` / 수현 체크 → "모임 생성" | 방 생성 → 3패널 채팅방 진입 |
| 3 | 지민 | 선호도 팝업 → 가능 시간: `평일 저녁` / 선호 장소: `강남` → "제출하기" | 팝업 닫힘, AI 패널에 "일정 조율을 시작하겠습니다" 표시 |
| 4 | 수현 | 알림/링크로 방 입장 → 선호도 입력 | 멤버 리스트 업데이트 |
| 5 | 민수 | 게스트 링크 클릭 → 닉네임 `민수` 입력 → "입장하기" | JWT 발급, 멤버 리스트에 `민수 (게스트)` 표시 |

> **시연 멘트**: "카카오톡 링크 하나로 앱 없는 친구도 바로 참여할 수 있습니다"

## ACT 2. 채팅 교착 → AI 자동 개입 (40초~1분) ⚡ 빨라짐

| Step | 누가 | 행동 | 시스템 반응 |
| --- | --- | --- | --- |
| 1 | 지민 | 채팅: "우리 이번 주에 밥 먹자! 언제가 좋아?" | 메시지 표시 |
| 2 | 수현 | 채팅: "나는 금요일 저녁이 좋은데" | 메시지 표시 |
| 3 | 민수 | 채팅: "금요일은 알바 있어서 안 돼 ㅠ 토요일은?" | 메시지 표시 |
| 4 | 수현 | 채팅: "토요일은 가족 모임이라 힘들어" | **교착 감지** (4메시지 누적, judge 호출) |
| 5 | 시스템 | Stalemate Judge 호출 → 교착 판정 | AI 패널 즉시: **"대화가 길어지네요, AI가 정리해볼게요 🗓️"** *(해결점 B)* |
| 6 | 시스템 | LangGraph 파이프라인 (5~10초, 노드1 스킵으로 단축) | AI 패널: **추천 카드** — "5월 8일 (금) 오후 6:00 (전원 가능)" + "확정하기"<br>※ 금/토는 거부 발언으로 자동 제외 *(해결점 F)*<br>※ **캘린더 패널: 금/토 셀 카운트 자동 감소** *(해결점 P)* |

> **시연 멘트** (포인트 강조):
> 1. *"카톡에서는 의견이 안 모이면 흐지부지 되잖아요. 매듭이 자동으로 감지해서 개입합니다."*
> 2. *"여기 보세요 — '금요일 알바', '토요일 가족모임'이라고 거부한 발언을 AI가 정확히 이해해서 카드에서 제외했습니다."*
> 3. *"캘린더 보세요. 금요일은 민수, 토요일은 수현이 안 된다고 했는데 카운트가 자동으로 갱신됐어요."* (해결점 P)
> 4. *"선호도에 평일 저녁을 입력했기 때문에 주말이 아닌 금요일 저녁 6시를 추천합니다."*

**변경 사항**:
- 임계값 4 (해결점 A) → 4번째 메시지에서 발화 → 5번째 메시지 안 쳐도 됨. 시연 시간 단축
- 분석중 메시지 즉시 (해결점 B) → 5~15초 대기 동안 사용자가 "AI가 일하는 중" 인지
- 자연어 거부 ISO 변환 (해결점 F) → 실제로 카드에서 금/토 빠짐 (시연 임팩트 ↑)
- 노드1 스킵 (해결점 C) → 1초 절약
- **자연어 거부 → 캘린더 카운트 동기화 (해결점 P, 임시 구현)**

## ACT 3. 캘린더 & TimeBar 시간 선택 (1분) — 변경 없음, 메시지 문구만 조정

> ACT 2에서 바로 확정해도 되지만, TimeBar 기능을 보여주고 싶으면 이 단계를 시연

| Step | 누가 | 행동 | 시스템 반응 |
| --- | --- | --- | --- |
| 1 | 지민 | 캘린더에서 5월 8일(금) 클릭 | 날짜 선택 표시 + 멤버 현황(3/3 가능) + TimeBar 표시 |
| 2 | 수현 | 캘린더에서 5월 8일(금) 클릭 | "수현님이 5월 8일 선택 중" 실시간 표시 |
| 3 | 민수 | 캘린더에서 5월 8일(금) 클릭 | "민수님이 5월 8일 선택 중" 실시간 표시 |
| 4 | 지민 | TimeBar에서 18:00~21:00 드래그 → 확인 | 선택 영역 파란색, 다른 멤버에게 실시간 공유 |
| 5 | 수현 | TimeBar에서 19:00~22:00 드래그 → 확인 | 겹치는 구간(19:00~21:00) 진한 색 |
| 6 | 민수 | TimeBar에서 18:00~22:00 드래그 → 확인 | **전원 시간 선택 완료 감지** |
| 7 | 시스템 | 자동 트리거 + TimeBar 데이터 주입 (해결점 I) | AI 패널 즉시: **"모두 시간 선택 완료! 일정 확정해드릴게요 📅"** *(해결점 B)* |
| 8 | 시스템 | LangGraph (3~5초, 노드1+3 스킵) | AI 패널: **추천 카드** — TimeBar 합의 시간(19:00~21:00) + 강남 장소 추천 (선호 데이터로 자동 반영) |

> **시연 멘트**: "When2Meet처럼 시간을 선택하면 실시간으로 겹치는 구간이 보이고, 전원 완료되면 AI가 자동으로 최적 시간을 찾아줍니다. **노드 2개를 스킵해서 평소보다 3초 빨라요.**"

**변경 사항**:
- 분석중 메시지 문구 (해결점 B) — "모두 시간대를 선택했어요!" → "모두 시간 선택 완료!"
- 노드1+3 스킵 (해결점 C) → ~3초 절약
- TimeBar 시간을 entity로 자동 주입 (해결점 I) → 추천 카드에 정확한 시간 채워짐

## ACT 5. 장소 추천 → 확정 (30~50초) ⚡ 빨라짐

| Step | 누가 | 행동 | 시스템 반응 |
| --- | --- | --- | --- |
| 1 | 지민 | AI 패널에 입력: "강남역 근처 한식 맛집 추천해줘" | quick_classify (정규식 ~ms) → `place` 분류 → **단축 경로** *(해결점 E)* |
| 2 | 시스템 | 단축 LangGraph (3~5초, 이전 6~15초) | **장소 추천 카드** 표시 (5개 장소 — 이름, 주소, 카테고리) |
| 3 | 지민 | 장소 하나 클릭 | **장소 상세 패널** (캘린더 패널에 카카오맵 지도 + 상세정보) |
| 4 | 지민 | **"이 장소로 확정"** 클릭 | 장소 확정 → **모임 생성 완료** (같은 meeting_id로 카드 갱신) *(해결점 J)* |

> **시연 멘트** (강조):
> 1. *"AI 패널에 직접 입력한 요청은 의도가 명확하니까, 매듭이 우회 노드를 건너뛰고 바로 장소 검색으로 갑니다. 평소 6~15초 → 3~5초입니다."*
> 2. *"장소 확정하면 같은 카드 안에서 갱신되는 게 보이시죠? 새로 만들어지는 게 아니라 같은 모임의 라이프사이클입니다."*

**변경 사항**:
- quick_classify 단축 경로 (해결점 E) → **6~15초 → 3~5초**
- meeting_id 카드 갱신 (해결점 J) → vote/place/maedeup 같은 카드로 누적 없이 진화
- 장소 카드 위치 분리 (2026-05-06): AI 패널에만 카드, 장소명 클릭 시 캘린더 패널에 상세

## ACT 6. (선택) Partial 카드 + 수동 입력 (30초) — 신규, 해결점 K 시연

> 시간 여유 있고 K 임팩트 보여주고 싶으면 추가. 빠듯하면 스킵.
> **전제 조건**: 어떤 멤버도 선호 장소를 입력하지 않음 (또는 별도 룸으로 시연)

| Step | 누가 | 행동 | 시스템 반응 |
| --- | --- | --- | --- |
| 1 | 지민·수현·민수 | (선호 장소 비워둠) TimeBar 전원 선택 | 시간만 합의됨 |
| 2 | 시스템 | all_members_selected → 장소 없음 → **partial maedeup_card** 발행 *(해결점 I)* | AI 패널: "5월 8일 (금) 19:00 ✅" + "🔍 장소 정해주세요 (클릭)" placeholder |
| 3 | 지민 | partial 카드의 장소 영역 클릭 | **장소 입력 모달** 표시 |
| 4 | 지민 | "강남" 입력 → 확인 | PATCH `/meetings/{id}/place` 호출 *(해결점 K)* |
| 5 | 시스템 | DB UPDATE + Kakao 좌표 + GCal event 등록 + 갱신 카드 재발행 | **같은 카드 갱신** — 장소 채워짐 + GCal 등록 표시 |

> **시연 멘트**: *"시간만 맞춰진 부분 카드도 즉시 발행됩니다. 장소가 정해지면 사용자가 클릭 한 번으로 입력하면 같은 카드가 갱신되고 캘린더에도 자동 등록돼요."*

**변경 사항**:
- 신규 시나리오 (해결점 I·J·K 임팩트 시연용)
- ACT 3과 별도 룸에서 진행하거나, 선호 장소 비워둔 시연 룸 따로 준비

## 시연 마무리 멘트

> "지금 보신 것처럼 매듭은 모임 조율 과정에서 발생하는 다섯 가지 문제를 해결합니다:
> 1. **의견이 안 모일 때** — AI가 자동 감지해서 개입 + **거부 발언까지 정확히 이해** *(F)* + **캘린더에 자동 반영** *(P)*
> 2. **시간 맞추기** — When2Meet 방식 + AI 최적 추천 + 선호 시간 반영 + **TimeBar 데이터를 entity로 자동 변환** *(I)*
> 3. **앱 없는 친구** — 링크 하나로 게스트 참여
> 4. **빠른 응답** — 사용자가 직접 입력한 요청은 단축 경로로 처리, 6~15초 → 3~5초 *(E)*
> 5. **카드 라이프사이클** — vote → 부분 → 완전 카드가 같은 자리에서 진화 *(J·K)*"

## 비상 대응 (체크리스트)

| 상황 | 대응 |
| --- | --- |
| Gemini API rate limit | 패턴 fallback으로 자동 전환됨 (정상 동작 보장) |
| WS 연결 끊김 | AI 패널 상단에 끊김 배너 자동 표시, 5초 후 재연결 시도 |
| TimeBar 데이터 추출 실패 | 로그 `TimeBar entity extraction failed` 확인, 일반 흐름으로 fallback |
| LLM judge가 stalemate 판정 안 함 | 5번째 메시지 추가 입력으로 카운터 누적 → 다음 60초 후 재판정 |
| Kakao API 키 누락 | 더미 슬롯 표시, 시연 영향 미미 |
| K 모달 PATCH 실패 | 모달에 에러 메시지 표시, 재시도 가능 |
| 캘린더 sync 실패 (해결점 P) | 로그 `[CHAT_UNAVAIL_SYNC]` 확인. 이름 매핑 실패 시 skip — vote_card는 정상 동작 |
