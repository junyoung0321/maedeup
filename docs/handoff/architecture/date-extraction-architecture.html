2핵심 — 안 되는 날 / 되는 날 추출 (2단계 구조)

단일 LLM에 "의도이해 + 날짜계산 + 여집합생성"을 한 번에 시키면 brittle했다(여집합 정확도 10%). 그래서 LLM은 '구조'만, 날짜 확장은 코드가 하도록 분리. (helpers/date_classify.py)

1
후보 달력 enumerate 코드 · 0ms
오늘 기준 향후 21일을 ISO+요일+상대태그로 나열. 2026-06-08(월)[다음주] … LLM이 날짜를 계산하지 않고 이 목록에서 조회만 하게 해 날짜 환각 제거.
2
가용성 '제약' 구조 추출 gpt-4o-mini (ENTITY)~2–6s
대화에서 구조만 뽑는다 — 날짜 나열 X. 각 제약: polarity(unavailable/available/preferred) · scope(this/next/week_after/range) · days(all/weekdays/weekend/요일들) · exclude_weekdays(여집합). AI 자신의 reflect-back 메시지는 무시하고 사람 발화만 본다.
"다음주 토요일 빼고 다 바빠" → {polarity:unavailable, scope:next_week, days:all, exclude_weekdays:["sat"]}
3
결정적 확장 + 정정 reconcile 코드 · 0ms
구조 → ISO 날짜 집합으로 코드가 확장(여집합·범위·요일 완전 보장). 그 후 rejected −= (available ∪ preferred) — "수요일은 돼" 같은 정정이 거부를 이긴다.
안 되는 날(rejected): 6/8·6/9·6/10·6/11·6/12·6/14  ·  되는 날(preferred/available): 6/13(토)
4
reflect-back 확인 코드 · 메시지 발행
비자명 해석(거부 2개+)이면 사용자에게 보여 교정 기회 제공. 잔여 추출 오차(eval F1 0.62)가 조용히 반영되는 대신 가시화.
📅 일정을 이렇게 이해했어요 — 어려운 날: 6/8(월)·6/9(화)…6/14(일). 제가 잘못 봤으면 알려주세요!
5
거부 날짜로 후보 슬롯 필터 _filter_out_rejected
free-slots 후보에서 rejected에 든 날짜를 제거(slot.start_at[:10] ∉ rejected). 남은 날짜만 추천 대상이 된다.

정확도(eval 103발화): rejected_dates F1 0.22 → 0.62, 여집합 exact 0.10 → 0.70. 잔여 오차는 4단계 reflect-back이 보완.
